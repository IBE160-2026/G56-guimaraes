## 1. Kontekst og Bakgrunn
* **Opprinnelig idé:** Fullautomatisert regnskapsanalyse med bilagstolkning (OCR), bankintegrasjon og avansert avviksdeteksjon.
* **Faglærers tilbakemelding:** Prosjektet var for omfattende og risikofylt for et 15-studiepoengs emne. Faglærer anbefalte å spisse prosjektet mot én kjerneflyt: **Saldobalanse (SB) og Hovedbok (HB)**.
* **Beslutning:** Omfanget ble kuttet drastisk ned. Vi konsentrerer oss 100 % om deterministisk avstemming og strukturert ledelsesrapportering via LLM.

## 2. Arkitekturprinsipper (The AI Firewall)
* **Prinsipp 1 (Deterministisk kjerne):** Språkmodeller skal *aldri* summere, subtrahere eller kalkulere regnskapstall. Alle beregninger, balansekontroller ($\sum D = \sum K$) og kryssavstemminger ($IB + \Delta HB = UB$) skjer i Python/Pandas.
* **Prinsipp 2 (Strukturert KI):** LLM benytter Pydantic Structured Outputs (`ManagementCommentary`) for å garantere typesikkerhet og forhindre hallusinasjoner.
* **Prinsipp 3 (Frakoblet sensormodus):** Sensor skal kunne kjøre hele applikasjonen offline uten API-nøkkel via innebygget mock-modus.
* **Prinsipp 4 (Norsk regnskapsstandard):** Alle kontoer mappes mot Norsk Standard Kontoplan (NS 4102). Appen må håndtere norske CSV-særegenheter (semikolon som skilletegn, komma som desimaltegn).

## 3. Nøkkelregler og Formler
1. **Dobbelt bokføringskontroll:**
   $$\sum \text{Debet} - \sum \text{Kredit} = 0 \quad (\pm 0.01 \text{ NOK})$$
2. **Kryssavstemming HB mot SB:**
   $$IB + \sum \text{Transaksjoner i HB} = UB \text{ i SB}$$
3. **Driftsresultat (EBIT):**
   $$\text{EBIT} = \text{Driftsinntekter} - \text{Driftskostnader}$$
